## Где мы

Сайт опубликован: https://baudi2.github.io/marshrut/ . Репозиторий: https://github.com/Baudi2/marshrut (публичный, ветка `main`). Каждый пуш в `main` запускает тесты, сборку и публикацию. Локально сайт запускается через `npm run dev`.

Идёт подготовка к большой переделке: вкладка «Лагерь» и лавка превращаются в город. Правила города уже написаны и просчитаны, сцены и интерфейса города на сайте нет. Baudi посмотрел плоские макеты, попросил вид сверху, настоящее 3D, анимации и прокрутку карты. Дизайн-агент сделал 3D-прототип. **Baudi посмотрел его: направление хорошее, но деталей мало — «больше low poly, чем полноценная 3D».** Нужно больше деталей на постройках, персонажах, в мире и декорациях. До решения, как добирать детализацию, сцену города на сайт не переносим.

## Последние решения Baudi (подробно — в `docs/DECISIONS.md`)

- Стиль моделей — Quaternius; KayKit не понравился.
- В игре нет мистики, магии и чудес: храмы и «чудеса» из набора не берём.
- У каждой постройки каждый уровень имеет свой облик, от простого к сложному.
- Игра не должна быть лёгкой; уровни и ранги должны иметь вес.
- Карта города прокручивается; сцена — 3D, вид сверху, с анимациями.
- Учёба идёт через Claude Code из облака, без ноутбука; Claude Docs не используем.
- Не экономить на разработке, дизайне и планировании.

## Что работает на сайте

- **Вкладки:** Сегодня, Путь, Лагерь, Задачи, Прирост, Навыки.
- **Циклы:** данные лежат в `data/cycles/01-basic-month/`, новый цикл — новая папка.
- **Очки:** XP за закрытые дни, задачи, артефакты; общий уровень без потолка, тяжёлый: уровень L открывается при 100·L·(L−1) XP.
- **Ранги навыков по зачёту:** ранг трека даётся за все выполненные условия цикла (`plan.json → tracks[].rank`), а не за опыт. На вкладке «Навыки» виден список условий.
- **Монеты и камни:** монеты — за ежедневный прогресс; камни — за недельные тесты (до 3), пройденные перевалы (по 1) и тестовое собеседование (1, не чаще раза в неделю).
- **Недельные тесты:** блок на вкладке «Путь» с готовым заданием для репетитора; вопросы помечаются кодом трека.
- **Стороннее развитие:** видео, статьи, встречи, тестовые собеседования вне плана; засчитываются только с записанными выводами. Список и таблица наград — на вкладке «Прирост».
- **Дуэль с собой:** попытка `duel` быстрее первой попытки на таймере.
- **Лавка и починка:** экипировка путника и постройки лагеря; долгий перерыв ломает одну-две купленные постройки.
- **Запустение:** пропуски рабочих дней видны в мире, очки не отнимаются.
- **Небо:** реальная погода из Open-Meteo, сезоны по дате, время суток по восходу и закату. Место выбирается на вкладке «Путь», там же предпросмотр.
- **Деплой работает:** `.github/workflows/deploy.yml`, первый запуск прошёл 18.11.2026.

## Защита и запись прогресса

Вопрос Baudi от 18.11.2026: может ли посторонний изменить прогресс, и может ли учебный агент заполнять его сам.

**Как сейчас.** Сайт статический: у него нет сервера и нет формы, которая что-то записывает. Прогресс — это JSON-файлы в репозитории. Изменить их может только тот, у кого есть право записи в репозиторий. Посетитель опубликованного сайта может только читать; покупки в лавке сохраняются в его собственном браузере и на данные Baudi не влияют. Публичный репозиторий открыт на чтение всем, включая неверные первые ответы, — так Baudi и выбрал.

**Откуда возможен риск:** взлом аккаунта GitHub (нужна двухфакторная защита); токен с правом записи, попавший в чужие руки или в код сайта; чужой запрос на слияние, принятый не глядя.

**Предложение, не реализовано.**
- Учебный агент работает как Claude Code или opencode с доступом к папке этого репозитория и пишет по правилам из `CLAUDE.md`: каждая запись — отдельный коммит, историю видно, любую правку можно откатить.
- Перед публикацией идут тесты блока «живые данные»: сломанная или невозможная запись не попадёт на сайт.
- Для агента сделать узкий вход — команду записи занятия, стороннего развития, теста, покупки, — которая сама проверяет данные, вместо правки JSON руками.
- Токены не хранить ни в коде сайта, ни в браузере. Вариант «сайт пишет сам через токен в браузере» из `docs/TOWN.md` поэтому не рекомендуется.
- Если понадобится жёстко отделить данные от правил игры, данные выносятся в отдельный репозиторий, и агент получает доступ только к нему.
