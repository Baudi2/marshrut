# Бриф: сайт-трекер «Базовый месяц Android» с геймификацией

> Это исходные вводные. Решения, принятые после них, записаны в `docs/DECISIONS.md` и главнее этого файла: данные переехали в `data/cycles/01-basic-month/`, уровень не имеет потолка, пропуски видны в мире. Состояние работы — в `docs/STATUS.md`.

Нужно сделать личный сайт, который превращает 30-дневный план восстановления навыков Android-разработчика в игру: показывает путь по дням, прирост за пройденное, решённые задачи LeetCode и текущий шаг. Этот файл — вводные для Claude Code и дизайн-агента. Данные лежат рядом: `data/plan.json` (план) и `data/progress.json` (журнал прогресса на 18.11.2026).

## 1. Пользователь и цель

- **Baudi**, Android-разработчик, 4+ года коммерческого опыта: Kotlin, Jetpack Compose, MVVM, Coroutines. Самооценка — middle+, цель — senior.
- **Зачем план:** выйти из застоя и вернуть базу, которая просела за год. Пробелы: алгоритмы почти забыты, с CI/CD не работал, System Design специально не изучал, Gradle знает поверхностно.
- **Режим:** около часа в рабочий день. Пн, ср, пт — дни с тренировкой, поэтому занятия лёгкие (30–45 мин); вт и чт — глубокие (60 мин).
- **Инструменты:** Claude Code для личных проектов, opencode на работе; Windows и Android Studio.
- **Репозитории:** `prep-basic` — заметки и решения (папки `algo/`, `design/`, `build/`, `notes/`); pet-проект — новый Android-проект Empty Activity для Gradle и CI.

## 2. Как устроен план

- **30 дней, 5 треков:** A — алгоритмы (Easy, по паттернам), B — System Design с основ, C1 — Gradle, C2 — CI/CD на GitHub Actions, E — ИИ-репетитор и unit-тесты. Описания, стартовый уровень и целевой результат каждого трека — в `plan.json → tracks`.
- **Три уровня дня:** минимум (10–15 мин, день засчитан), ядро (шаги дня), расширение (+60 мин по желанию в глубокие дни).
- **Артефакт — единица прогресса, не минуты.** Каждое занятие оставляет файл в репозитории: решение, заметку, схему, workflow.
- **Повтор встроен в ядро:** занятие по алгоритмам начинается с решения прошлой задачи с пустого редактора. Через 2–3 недели три задачи решаются без подсказок (день 29).
- **Замер в начале и в конце:** baseline в день 2 (задача на таймере и самооценка 1–5 по пяти трекам) сравнивается с днём 28; день 30 — ретро и цели следующего цикла.
- **Идём по номерам дней, а не по календарю.** После дня 1 была пауза в две недели; план продолжился с дня 2. Даты `plannedDate` в `plan.json` — исходный график, они нужны только как подсказка дня недели.
- **Занятия ведёт Claude в чате по одному шагу:** что открыть → что сделать → когда готово → что написать в ответ. Большие таблицы с планом пользователю неудобны — это главный вывод для интерфейса.

## 6. Геймификация

Числа ниже — стартовые значения. Подобрать пороги так, чтобы полностью пройденный план давал максимальный уровень.

| За что | XP |
| --- | --- |
| День закрыт на минимуме | 10 |
| День закрыт ядром: лёгкий / глубокий | 30 / 50 |
| Расширение | +25 |
| Задача решена сама на таймере | 20 |
| Задача решена после разбора | 10 |
| Повтор с пустого редактора удался | 15 |
| Задача решена без подсказок через 2–3 недели | 30 |
| Задача-пара | 10 |
| Артефакт сохранён в репозитории | 10 |
| Workflow впервые зелёный / красный CI починен | 40 / 20 |
| Неделя закрыта по чекпоинту | 50 |
| Вернулся после паузы от 7 дней | 20 |

- **Уровни:** общий уровень по XP и отдельный ранг по каждому треку.
- **Ключевые точки пути («боссы»):** baseline дня 2, первый зелёный workflow (день 7), первый собственный мини-дизайн (день 20), baseline-финал (день 28), три задачи без подсказок (день 29), ретро (день 30).
- **Побочные задания:** задачи-пары и расширения. Они не обязательны и не блокируют путь.
- **Ритм вместо серии дней:** считать занятия за неделю и закрытые недели, а не непрерывные дни подряд. Правило плана — цепочка не рвётся дважды подряд.
- **Достижения, примеры:** «С пустого редактора» — первый удачный повтор; «Зелёный» — первый успешный CI; «Красный → зелёный» — починил упавший CI; «Архитектор» — первый свой мини-дизайн; «Три без подсказок» — день 29; «Быстрее себя» — baseline-финал лучше стартового; «Возвращение» — занятие после паузы; «Коллекция паттерна» — все задачи одного паттерна решены.

## 7. Идеи на потом

1. **Дуэль с собой.** Перерешать старую задачу и сравнить время с первой попыткой.
2. **«Могу объяснить».** Список формулировок уровня собеседования, которые открываются по мере прохождения: «три фазы сборки Gradle», «implementation против api».
3. **Отчёт недели.** Автотекст на пять строк для отправки другу или в свой канал — этого требует пятничное ревью.
4. **Живые данные с GitHub.** Календарь коммитов `prep-basic`, статус CI pet-проекта бейджем.
5. **Плановое и фактическое время.** Сколько минут заложено и сколько ушло, по шагам и по трекам.
6. **Квиз по своим заметкам.** Режим проверки по колоде; в плане это день 23.
7. **Карта цикла 2.** Закрытая область за ретро: Medium-задачи, модуляризация и convention plugins, платформенный трек, KMP-проект.
8. **Запись занятия с сайта.** Форма «закрыть шаг», которая сохраняет черновик локально и выгружает JSON-патч для `progress.json`.
9. **Снимок навыков в конце.** Страница-итог после дня 30: что было, что стало, какие артефакты остались.
10. **Версия для телефона.** Открыть текущий шаг и таймер с мобильного.

## 8. Принципы

- **Один шаг на экране.** Главная страница показывает, что делать сейчас, а не весь план.
- **Очки за результат, а не за клики.** XP даются за артефакт, решение, повтор, зелёный CI.
- **Паузы не наказываются.** Перерыв показывается как привал на пути; возвращение поощряется.
- **Честные цифры.** «Решил сам» и «решил после разбора» — разные статусы, и оба нормальны.
- **Прирост важнее объёма.** На первом плане сравнение с собой в начале, а не число закрытых дней.

## 9. Для дизайн-агента

- **Аудитория:** один взрослый разработчик. Тон спокойный и уважительный, без детской мультяшности и без давления.
- **Метафора на выбор:** маршрут с привалами и перевалами либо дерево навыков. Маршрут лучше ложится на «путь по дням» и на паузы.
- **Ключевые экраны:** «Сегодня» с одним шагом; карта пути; сетка задач; экран прироста «было → стало».
- **Состояния узла дня:** впереди, текущий, сделан на минимуме, сделан ядром, с расширением, пропущен, буферный.
- **Состояния задачи:** пять статусов из раздела 4, плюс пометка «повтор запланирован».
- **Практика:** язык интерфейса русский; тёмная и светлая темы; моноширинный шрифт для кода и команд; телефон — полноценный сценарий для экрана «Сегодня».

## 10. Техника и ограничения

- **Статический сайт без бэкенда**, один пользователь, данные из JSON в репозитории. Стек — на усмотрение Claude Code.
- **Хостинг:** GitHub Pages из публичного репозитория. В приватных репозиториях у пользователя закончился лимит минут GitHub Actions; в публичных Actions бесплатны.
- **Деплой через GitHub Actions** — заодно практика по треку CI/CD.
- **LeetCode:** официального API нет. Статусы задач вести вручную в `progress.json`, без парсинга сайта.
- **Личные данные:** в публичном репозитории окажутся прогресс и первые ответы на вопросы. Если это нежелательно, вынести `knowledgeChecks` и `observations` в файл вне репозитория.
